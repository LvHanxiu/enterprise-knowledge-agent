# AI 辅助使用记录

## AI 承担的工作

本次工程由 Codex 根据用户提供的两张题目截图协助完成。AI 负责提取需求、设计协议、实现 Agent 主循环、模型适配、检索与合成数据、CLI、自动化测试、示例运行和工程文档。并行协作分别负责检索、模型适配、独立验收与文档，再由主流程整合验证。

查阅供应商官方文档，核对 Chat Completions 和 JSON 输出行为：

- [Structured model outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
- [Create chat completion](https://developers.openai.com/api/reference/python/resources/chat/subresources/completions/methods/create)
- [阿里云 Model Studio Structured output](https://www.alibabacloud.com/help/en/model-studio/qwen-structured-output)

JSON 模式不保证业务参数满足协议，因此没有把解析成功当作可信结果。程序校验动作格式、已读取的逐字原文引用、结果结构和执行预算；问题相关性、适用范围、业务冲突及下一步动作由真实模型判断。冲突结果需要至少两条不同的有效引文，程序不再用人工事实索引代替模型裁判业务语义。

## 人工输入与修改的边界

已知的人工参与是提供题目、指定完整工程交付、要求不添加多余代码注释，以及确认本次只在本地完成、GitHub URL 后续补充。用户随后明确要求再次对照题目检查符合性、遗漏和过度防御，触发了本轮独立复核与修改。没有把 AI 的修改描述成提交人手工编写，也没有虚构提交人额外完成的学习、调试、个人修改或独立测试。后续若由提交人修改，应在 Git 中留下实际差异，并相应补充此记录。

## 关键审查与验证

初次审查关注模型是否真正看到工具返回再选择动作、原文引用是否真实、版本日期是否被误当优先级、工具故障及预算耗尽是否仍错误输出成功，以及日志是否混淆真实模型与 Mock。

再次审查发现此前防御规则会拒绝正确结果：未索引的真实原文不能回答、没有 `facts` 的冲突不能报告、同一事实键的不同适用范围被强制判为冲突、历史宽泛搜索截断会阻止后续精准检索完成。AI 用可执行反例复现这些问题后，移除了相应硬判定。正文改动不再要求同步修改辅助事实索引，原文成为最终引用依据。

同时完成了以下修订：

- 将 Mock 改为必须显式选择的预设场景，只测试工具流程、状态和记录；不再把它描述为理解任意自然语言的问答模型。
- 移除对所有 `Exception` 的笼统捕获，预期模型及工具错误仍有明确状态；意外编程错误保留异常，避免被伪装成正常业务失败。
- 修正普通 wheel 安装后的资源定位，将知识库、验收输入和测试资源随安装包提供。
- 调整单元测试，保留协议、读取、逐字完整引文及预算约束，并加入先前被错误拒绝的正确答案。范围识别、冲突及问题理解改由真实模型验收。
- 新增八组真实反例场景。首次扩展验证发现模型对“已命中文档但具体规则缺失”的问题仅看摘要便判定不足，因此补充读取完整原文的提示要求，并重新执行真实验收；各批次和单项复测结果见评估文档。

测试期望、各批次实际结果、运行文件和限制统一记载于 [03-evaluation.md](03-evaluation.md)。提示修改本身不等于问题已经通过验收；应查看对应版本的真实运行记录。不能将单元测试中的脚本决策或 Mock 结果解释为模型推理能力。运行记录中的 `model.mode` 明确区分 `live`、`mock` 和 `scripted`。

## 数据与密钥

仓库知识资料均为合成数据。模型配置从环境变量读取；密钥不进入源码、示例文件、Trace 或提交。真实运行如使用外部服务，只发送本项目的合成问题、合成文档及对应观测，不接入真实企业资料。
