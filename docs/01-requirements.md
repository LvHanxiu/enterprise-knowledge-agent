# 需求与验收

## 用户、目标与范围

员工需要查询企业制度及产品说明，并获得可以回查原文的可靠答案。本项目以合成知识库演示该流程，输入为自然语言问题和可选的对话历史，输出为答案、文档 ID、版本日期、原文片段、资料缺口、澄清问题和任务状态。

交付选择 Python CLI。界面、线上部署、多 Agent 生产调度、真实企业资料接入均不属于本次实现范围。所有演示资料均为合成内容，不代表真实企业制度。实现包括真实模型接入与明确标识的离线 Mock，不能用 Mock 的成功率证明真实模型决策质量。

## 必须实现的行为

| 要求 | 实现与验收方式 |
| --- | --- |
| 模型动态决策 | 每轮将问题、历史、工具观测、剩余预算交给模型；模型选择检索、读原文、结束或追问；真实模型运行记录见 `examples/` |
| 明确答案 | 读取支持结论的原文后输出完整引文及 ID、版本日期 |
| 文档冲突 | D01 报销期限为 30 天，D02 为 15 天；核验双方、同时引用、指出适用范围及优先级未说明，不按版本日期擅自裁决 |
| 资料外问题 | 检索后没有依据时返回 `insufficient` 与资料缺口，不凭常识生成答案 |
| 改写问题 | 结合中文词项及别名检索，并允许模型依据空结果补充检索 |
| 上下文追问 | 传递用户和助手历史；支持代词回指；历史不能代替可引用的文档 |
| 信息不足 | 对缺少产品名或员工适用范围的问题使用 `clarify`，返回 `needs_clarification` |
| 工具失败 | 结构化反馈失败给模型，由后续模型动作决定重试、换检索或结束；演示支持一次失败及持续失败注入 |
| 引用真实性 | 仅引用成功读取的原文；逐字校验完整句子；拒绝伪造引文、搜索摘要冒充原文及截去句内限定范围 |
| 文档替换核验 | 将报销期限正文改为 45 天，即使旧事实提示未同步，新结果也应使用新正文；旧引文必须被拒绝 |
| 有限执行 | 同时限制模型步数与工具次数；请求继续使用已耗尽的工具预算或达到模型步数上限时返回 `incomplete` |
| 可复现交付 | 源代码、测试、依赖声明、环境变量示例、运行命令、至少三组输入和实际输出、Trace、设计与复盘文档 |

输入不能被附加为“必须手工维护事实索引”。本次复核增加了普通无索引文档、正文独立更新、未索引新句、不同适用范围、无关冲突、显式指代等验收，见 `examples/review-cases.json`。业务语义由真实模型决策；离线 Mock 必须显式选场景，仅验证流程。

## 成功标准

1. 运行 README 所列命令可启动 CLI，并可在无密钥时通过显式 Mock 模式走完完整流程。
2. 正常、资料不足和工具失败至少三组样例均保留输入、实际结构化输出和逐步 Trace；验收场景不限于三组。
3. 至少两条真实模型轨迹展示工具观测不同导致后续动作变化；如真实服务不可用，必须记载失败、边界与复现方式，不能伪造真实模型效果。
4. 可执行测试覆盖成功路径以及引用、冲突、预算、异常处理的重要失败路径。
5. 最终提交记录标明题号、仓库 URL、commit SHA；未实际创建的远程仓库不得虚构地址。当前工程提供本地 Git 交付，远程发布状态以提交说明为准。

## 输出状态

| 状态 | 含义 |
| --- | --- |
| `answered` | 基于已核验原文作答，所选证据无已知未处理冲突及资料缺口 |
| `conflict` | 已核验同一规则存在不同值，需要确认适用制度或优先级 |
| `insufficient` | 已尝试检索，资料不足以作答 |
| `needs_clarification` | 缺少关键问题条件，需要用户补充 |
| `incomplete` | 执行预算不足，未完成核验 |
| `error` | 预期模型服务或适配器错误，未完成核验；编程异常不被伪装成业务结果 |

检索范围和已读取资料决定可证明的边界：`answered` 不表示已经穷尽所有可能存在的企业文件。
