# 方案与技术取舍

## 原生模型驱动循环

本项目使用 Python 标准库实现 Agent 循环，减少安装和运行负担。每一轮把问题、对话历史、已观察的工具结果和剩余执行预算发给模型；模型只返回下一步动作及简短可审计依据。程序验证动作协议后执行工具，再把返回结果交给下一次模型调用。固定代码负责约束和校验，具体下一步由模型选择。

```text
问题与可选历史
    ↓
模型选择单步动作 ← 工具返回 / 校验失败 / 剩余预算
    ↓                         ↑
动作协议校验 → search / read ──┘
    ↓
finish / clarify → 引用与结果结构校验 → 结果及 Trace
```

真实模型适配器使用兼容 Chat Completions 的 HTTP 接口。模型 JSON 输出仍需运行时校验，JSON 语法正确不等于参数及业务语义正确。解析失败、拒绝、超时和服务错误必须成为明确状态，不能自动冒充 Mock 结果。

## 工具与知识结构

`search(query, limit)` 返回文档 ID、标题、版本日期、检索摘要、分数和规则键。`read(doc_id)` 返回该文档原文及合成的结构化事实。检索摘要仅用于选择要读的资料，不能直接作为最终引用。

文档只要求 `doc_id`、`version_date`、`content`。`title` 缺省为文档 ID；`keywords`、`facts` 缺省为空数组。事实提示中的 `key`、`value`、`quote` 仅用于辅助检索，不能代替原文。正文更新后，失效事实提示会被忽略并显示 `index_warnings`，不会阻止读取新原文。检索采用适合小规模中文资料的本地词法检索；不声称达到大规模企业语义检索的召回水平。

## 动态决策示例

| 观测 | 可选择的下一步 |
| --- | --- |
| 首次搜索为空，但可识别同义表达 | 换查询词补充检索 |
| 搜索找到相关摘要 | 读取原文核验 |
| 同一规则检索到两个来源 | 逐一读取，再判断是否冲突 |
| 原文明确且没有已知冲突 | 选择原文引文并结束 |
| 缺少产品名称或员工条件 | 追问补充条件 |
| 工具临时失败 | 依据失败信息选择重试或其他动作 |
| 检索后仍无支持资料 | 停止，说明资料缺口 |

这些路径必须以实际模型动作及观测记录为证据。离线 `MockModel(scenario)` 只执行显式 JSON 场景，动作和业务状态由场景预置，引用从实际读取的当前原文提取；它不理解问题、不判断语义冲突。测试用 `ScriptedModel` 同样是流程替身，二者不属于真实模型自主决策效果证明。

## 引用与冲突约束

最终答案采用抽取式表述。模型选择需要展示的原文，程序以文档 ID 和版本日期组织答案，不接受模型附加自由发挥的制度结论。这减少了“引用正确但答案虚构”的风险，也牺牲了一部分自由摘要的自然度。

只有成功 `read` 的文档可以引用。引用必须逐字存在且是完整句子或连续完整句子，防止仅摘数字、删去句内限定词；分号不作为可截断范围的句末。引用不需要预先出现在事实索引里。报告 `conflict` 时至少展示两条不同的已读引文，附资料缺口及澄清请求。

模型根据正文判断相关性、适用范围、显式替代关系和冲突。总部与分公司的不同期限不会因相同 `fact.key` 被程序强判冲突；没有事实索引的原文也能用于发现冲突。搜索的 `truncated`、`total` 供模型判断是否补充检索或换更精确的查询，旧的宽泛查询不会永久阻止回答，也不要求读取无关候选。模型不能仅凭版本日期选择制度，不能在只看摘要时声称已核验全文。

唯一已核验来源能直接回答一般性问题时，可以按该来源回答；不凭空要求员工类型、产品版本或证明不存在未知制度。明确的用户限定与文档范围不一致时，不能跨范围代答。`clarify` 用于用户可以补充的必要问题条件；清晰问题的检索覆盖缺口或工具不可用用 `insufficient` 表达，不反问用户答案本身。

这些校验保证引用来自实际原文及输出结构一致，不保证自然语言语义一定正确。是否适用、是否冲突、引文是否回答当前问题由模型负责，并通过真实语义场景验收；不把机械的字符串或字段比较包装成完整语义证明。

## 错误、预算与 Trace

预期工具错误和动作校验错误以结构化观测反馈给模型。程序不在工具函数里安排固定业务重试；下一次动作由模型选择。预期模型服务错误返回 `error`；意外编程异常向上抛出，不用宽泛的 `except Exception` 掩盖缺陷。工具调用次数和模型步数分别计数，失败工具调用也消耗预算。达到工具次数上限后仍可基于已有充分证据结束；若继续请求工具则返回 `incomplete`。达到模型步数上限还没有合法结果也返回 `incomplete`。

Trace 保存步骤号、动作、参数、简短决策依据、返回摘要及观测结果。只记录外部可审计事件，不要求或保存模型内部思维链。真实模型名称、运行模式、使用量和用时随结果输出，便于把真实与模拟运行区分。

## 扩展方向

保持 `decide(state)` 和工具接口后，可更换模型供应商、检索实现或知识来源。进一步面向生产需要补充权限隔离、文档更新和撤回、规则适用性与优先级、检索召回评估、敏感信息治理以及人工升级处理；本次不宣称已经具备这些能力。
