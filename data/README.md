# 合成知识库

所有示例文档均为本工程编写的虚构材料，不代表任何真实企业制度。文档 ID、版本日期、原文和可选索引提示在同一个 JSON 对象内保存。原文始终是答案依据，事实提示不能替代原文，也不能单凭相同事实键判定冲突。

`knowledge_base.json` 包含报销冲突、VPN、年假、发票、协作云产品与密码重置材料。D01 与 D02 对同一报销期限分别给出 30 天和 15 天，且没有适用范围、优先级或替代关系；不能仅凭版本日期选定答案。

`single_policy.json` 只包含 D01，用于验证单一可靠来源可以给出 30 天答案。`changed_policy.json` 只包含修改后的 D01，期限为 45 天，事实值和原文引用同步修改；用于验证替换文档后答案随证据变化。

知识库顶层为文档数组。每份文档只必须包含非空字符串 `doc_id`、`version_date`、`content`，日期采用有效的 `YYYY-MM-DD`。文档 ID 是不用于文件访问的标识，可使用中文，不能重复。`title` 可省略，默认使用文档 ID；`keywords` 和 `facts` 可省略，默认空数组。示例文档额外标注 `synthetic: true`。

可选 `facts` 的每条提示包含 `key`、`value`、`quote`。加载时检查 `value` 是否是 `quote` 的逐字子串、`quote` 是否在当前原文中。失效或格式错误的提示会被忽略，搜索结果和读取结果的 `index_warnings` 会说明原因，不会阻断原文读取或继续使用旧值。相同事实键可以出现在多条提示中；是否冲突、范围是否适用，由模型结合原文判断。

新增段落不必补写事实提示；只修改原文也可以重新运行，例如把 D01 的 30 天改为 45 天后，旧提示会被丢弃，检索与读取均返回新原文。文档数量与原文长度没有人为业务上限；大规模资料的内存消耗和模型上下文容量仍是本地实现的实际限制。

检索采用中文双字片段、英文词项、BM25 风格评分和少量中英文领域同义词。检索返回摘要、有效事实 key、`total`、`hits` 和 `truncated`；Agent 必须读取原文才能引用。`truncated` 只说明本次候选是否被数量参数截断，模型可根据相关性决定缩小查询、补查或结束，不要求读尽无关候选。小规模词法检索无法覆盖所有表达方式，不等价于完整语义检索；缺失材料应作为资料缺口返回。
